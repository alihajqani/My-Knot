# Data leakage

## In my own words
> data leakage نمیدونم  چیه ولی حسم اینه که از روی متن بیاد و یک جوری بایاس بشه.
>
> قطعا گزارش نمیکنم چون data leakage داریم. اگر بخوام درست تست کنم کپشن ها رو بر میدارم و بدون کپشن نگاه میکنم چقدر دقت دارم.

## Correction
- اسمش bias نیست. leakage یعنی جواب از راهی وارد ورودی شده که موقع استفاده‌ی واقعی وجود نداره.
- کپشن رو نباید دور ریخت. از **ورودی** حذفش کن، ولی به‌عنوان **label** (کلید تصحیح) نگهش دار.

## Simple version
امتحانی که جواب‌هاش پایین همون برگه چاپ شده. همه ۲۰ می‌گیرن و این نمره هیچی درباره‌ی بلد بودن درس نمیگه.

## Technical version
- leakage همیشه نسبت به **شرایط استفاده‌ی واقعی** تعریف میشه. اگه ۱۰۰۰ تصویر نهایی هم کپشن داشته باشن، خوندن کپشن leakage نیست و یه ویژگی مشروعه. پس اول باید از مشتری پرسید.
- شکل‌های رایجش: جواب توی ورودی باشه (کپشن)، یه تصویر هم توی train باشه هم توی test (duplicate یا frameهای پشت‌سرهم)، یا از اطلاعات آینده استفاده بشه.
- نتیجه‌اش همیشه یکیه: عدد ارزیابی الکی بالا درمیاد و روی دیتای واقعی سقوط می‌کنه. یه جور مشکل validity توی ارزیابیه ← [[reliability-vs-validity]].
- برای ادعای D2 (۲۰٪ بهتر از دیتاست‌های عمومی): باید بتونی توضیح بدی test set یکسان بوده و هیچ تصویری (یا frameهای نزدیک به هم) توی train و test مشترک نبوده.

## Exercise (no AI)
توی یه فایل Python خالی ۱۰۰ «عکس» فرضی بساز که ۲۰ تاشون duplicate باشن. یه split تصادفی train/test انجام بده و بشمر چندتا duplicate بین دو طرف نشت کردن. بعد split رو طوری بازنویسی کن که duplicateها همیشه سمت یکسانی بیفتن (group split).

## Flashcards
data leakage چیه؟::وقتی جواب از راهی وارد ورودی یا train میشه که موقع استفاده‌ی واقعی وجود نداره، و عدد ارزیابی الکی بالا درمیاد.
با کپشن «روز پدر» زیر پوستر چی‌کار می‌کنی؟::از ورودی مدل حذفش می‌کنی (crop) و به‌عنوان ground truth برای field مناسبت نگهش می‌داری.
چرا leakage به شرایط استفاده‌ی واقعی بستگی داره؟::اگه موقع استفاده‌ی واقعی هم کپشن وجود داشته باشه، خوندنش تقلب نیست و یه ویژگی مشروعه.
